# 🥑 Вкусный ассистент — AI-помощник по продуктам ВкусВилла

Личный проект курса **МФТИ · VK Education** (РК1, защита 27 октября 2026).

**Задача:** универсальный чат-ассистент по продуктам ВкусВилла. Пользователь
описывает потребность свободным языком — «перекус на работу, бюджет 500 ₽,
без лактозы» — а ассистент сам решает, какие инструменты вызвать: ищет реальные
товары, проверяет составы, показывает карточки и собирает корзину ВкусВилла
со ссылкой на vkusvill.ru. Никаких форм и фильтров — только диалог.

**Работающий сервис:** http://176.12.68.185

## Пользователь и сценарий использования

**Пользователь** — покупатель ВкусВилла, который хочет быстро сформировать
покупку, но не хочет вручную лазить по каталогу и сверять составы: люди
с пищевыми ограничениями, ограниченным бюджетом или просто без времени.

**Сценарий использования:**

1. Пользователь: «Подбери продукты для полноценного обеда для одного
   взрослого человека»
2. Ассистент подбирает сбалансированный набор — основное блюдо, гарнир,
   овощи, напиток (search_products); при пищевых ограничениях проверяет
   составы (get_product_details); показывает карточки с ценами
3. Пользователь: «Собери всё это в корзину» (или выбирает отдельные позиции)
4. Ассистент собирает корзину (create_cart) — в чате появляется кнопка
   «Открыть корзину ВкусВилл» с итоговой суммой
5. Пользователь уточняет: «добавь ещё кофе», «убери печенье» — корзина
   обновляется в рамках того же диалога

Другие сценарии: подбор аналогов («замени на безлактозное»), скидки,
рецепты с ингредиентами из каталога, адреса магазинов.

## Границы MVP

**В MVP входит:** поиск товаров, карточки, детали состава/КБЖУ, аналоги,
скидки, рецепты, магазины, сборка корзины со ссылкой, стриминг ответов,
история чата в браузере.

**В MVP не входит (осознанные границы):**

- **OAuth-инструменты MCP** (история заказов, персональные скидки, LP) —
  требуют OAuth 2.0 + PKCE, это отдельный проект; заявлено в roadmap
- **Персонализация цен по региону** — цены каталога без привязки к точке
- **LLM-судья в eval** — осознанное ограничение объёма РК1, проверки
  детерминированные
- **Мобильные приложения / TG-бот** — только веб-интерфейс

**Критерии готовности:** полный сценарий «потребность → подбор с проверкой
ограничений → корзина со ссылкой» работает на проде; все оффлайн-тесты
зелёные; 7 eval-кейсов проходят; при недоступности MCP пользователь получает
вежливое сообщение об ошибке, а не 500.

## Архитектурная схема системы

```
Браузер (vanilla JS, fetch + ReadableStream)
   │  POST /api/chat {messages} — вся история, сервер без состояния
   ▼
nginx (:80, proxy_buffering off для SSE)
   ▼
FastAPI + uvicorn (127.0.0.1:8000)
   │  lifespan: один MCPClientManager на приложение
   ▼
Агентный цикл (app/agent.py, максимум 6 итераций)
   │  YandexGPT (OpenAI-совместимый API, стриминг, function calling)
   │      ▲ токены → SSE-события → браузер
   ▼
Обёртки инструментов (app/tools/vkusvill.py) — 7 инструментов
   │  валидация аргументов, зачистка результатов, события products/cart
   ▼
MCPClientManager (app/mcp_client.py)
   │  семафор против rate limit, ретраи, auto-heal сессии
   ▼
MCP-сервер ВкусВилла (https://mcp.vkusvill.ru/mcp, streamable HTTP)
```

Ключевое правило слоёв: `agent.run(messages, emit)` не знает ни про FastAPI,
ни про HTTP — веб-эндпоинт, eval-раннер используют один и тот же цикл.
Состояние корзины переносится служебными блоками `[В корзине: …]` в истории
(фронтенд дописывает, бэкенд вырезает и переносит в системный промпт —
модель их не видит в сообщениях).

Подробности: [docs/architecture.md](docs/architecture.md).

## Схема MCP-интеграции

Клиент официального MCP-сервера ВкусВилла (`mcp.vkusvill.ru/mcp`,
протокол 2025-03-26, streamable HTTP, stateless — из 11 инструментов
используются 8). LLM видит **7 обёрток**, а не сырые MCP-инструменты:

| Инструмент LLM | MCP-инструмент | Что делает обёртка |
|---|---|---|
| `search_products` | `vkusvill_products_search` | режим custom, компактные поля, событие карточек |
| `get_product_details` | `vkusvill_product_details` | только состав/КБЖУ/цена, зачистка HTML |
| `find_product_analogs` | `vkusvill_product_analogs` | топ-10 аналогов |
| `search_discounted_products` | `vkusvill_products_discount` | old_price для UI |
| `find_recipes` | `vkusvill_recipes` | заполняет 8 обязательных параметров, кэш id аллергенов |
| `find_shops` | `vkusvill_shops` | топ-5 адресов |
| `create_cart` | `vkusvill_cart_link_create` | валидация 1–20 позиций, дедуп, пересчёт суммы, инварианты накопления |

Не выставляются: barcode-поиск (нишевый) и 3 OAuth-инструмента.

Обёртки нужны, потому что сырой `vkusvill_recipes` требует 8 обязательных
параметров (LLM его не вызовет корректно), выдача поиска содержит
HTML-сущности и картинки (токены), а `create_cart` без обёртки позволял
модели молча терять позиции корзины (см. разбор ошибок).

Полная схема: [docs/mcp_integration_schema.md](docs/mcp_integration_schema.md).

## AI-логика: агент

**Модель:** YandexGPT через OpenAI-совместимый API Yandex AI Studio
(function calling, стриминг).

**Агентный цикл** (`app/agent.py`): LLM получает системный промпт с
динамическим контекстом (показанные товары, текущая корзина) и 7 схем
инструментов. В одном ходе модель может несколько раз вызвать инструменты —
аргументы tool calls приходят фрагментами и накапливаются по index;
невалидный JSON возвращается модели как `TOOL_ERROR` для самокоррекции.
Цикл ограничен 6 итерациями.

**Инварианты в коде, а не в промпте.** Каждый обнаруженный сбой модели
закрывается гарантией в коде (`app/agent.py`, `app/tools/vkusvill.py`):

- корзина может только **накапливаться**: флаг `replace` игнорируется,
  удалить позицию можно только явно (`quantity=0`), не упомянутые позиции
  всегда остаются;
- повторный `create_cart` в том же ходе объединяется с результатом
  предыдущего (`_final_cart`), а не затирает его;
- если модель «обновила корзину словами» — regex-детектор утверждения
  принудительно требует вызов инструмента, а обещание ссылки ведёт к
  детерминированному пересбору корзины без LLM;
- удаляемый товар сверяется с репликой пользователя (просили убрать
  печенье — модель не может убрать суп без `confirm_removals`);
- «удаление умолчанием»: «убери винегрет» убирает винегрет, даже если
  модель передала состав без его id.

Промпты: системный (`app/prompts.py`), динамический контекст и
принудительные поправки (`app/agent.py`), описания инструментов
(`app/tools/schemas.py`).

## Инструкция по запуску и развёртыванию

**Локально:**

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env       # заполните LLM_API_KEY (Yandex AI Studio)
.venv/bin/uvicorn app.main:app --reload
# откройте http://127.0.0.1:8000
```

**Переменные окружения** (`.env`):

| Переменная | Описание |
|---|---|
| `LLM_API_KEY` | ключ Yandex AI Studio |
| `LLM_BASE_URL` | `https://ai.api.cloud.yandex.net/v1` |
| `MODEL_NAME` | `gpt://<folder_id>/yandexgpt/latest` |
| `MCP_URL` | `https://mcp.vkusvill.ru/mcp` |
| `MAX_TOOL_ITERATIONS` | лимит шагов агентного цикла (6) |
| `TOOL_RESULT_MAX_CHARS` | обрезка результатов инструментов (6000) |

**Тесты и eval:**

```bash
.venv/bin/python -m pytest tests/ -q        # 44 оффлайн-теста: fake LLM + fake MCP, без ключей
.venv/bin/python -m evals.runner            # 7 кейсов на живых LLM + MCP → docs/eval_report.md
```

**Прод (VPS, Ubuntu 24.04):** uvicorn как systemd-сервис `vkusvill`
на `127.0.0.1:8000`, nginx проксирует `:80` с `proxy_buffering off`
(иначе SSE не стримится). Публичный URL: http://176.12.68.185.
Обновление:

```bash
git push                                    # сначала push, потом pull на сервере
ssh root@176.12.68.185 "cd /opt/vkusvill && git pull && systemctl restart vkusvill"
```

**Структура репозитория:**

```
app/
├── main.py        # FastAPI: SSE-эндпоинт /api/chat, статика, lifespan
├── agent.py       # агентный цикл (LLM → инструменты → LLM → ответ)
├── mcp_client.py  # MCP-сессия: ретраи, auto-heal, троттлинг
├── prompts.py     # системный промпт
├── config.py      # настройки (pydantic-settings, .env)
├── events.py      # SSE-события
├── tools/         # обёртки MCP-инструментов + схемы для LLM
└── web/           # чат-UI (Jinja2 + vanilla JS, без сборки)
evals/             # 7 eval-кейсов + раннер (docs/eval_report.md)
tests/             # 44 оффлайн-теста (pytest, fake LLM + fake MCP)
docs/              # схема MCP, архитектура, eval-отчёт
scripts/           # spike-скрипты (smoke_mcp, smoke_agent)
presentation.html  # интерактивная презентация для защиты
```

## Результаты Eval и разбор ошибок

Прогон от 23.10.2026, живые YandexGPT + MCP: **7/7 кейсов PASS**
(бюджет ≤ 500 ₽, аллергены, скидки, пустой результат, уточнение,
недоступный MCP). Полный отчёт: [docs/eval_report.md](docs/eval_report.md).

**Ошибки, найденные eval-раннером** (исправлены на старте):

1. *Корзина не собиралась* — на «положи в корзину» модель переспрашивала
   «собрать?». Фикс: правило промпта — при прямом запросе сразу вызывать
   `create_cart`.
2. *Рецепты вместо товаров* — «подбери завтрак без лактозы» вёл в
   `find_recipes`. Правки промпта не помогали; помогло усиление **описаний
   самих инструментов** — выбор инструмента LLM определяется в первую
   очередь ими.
3. *Обещание без действия* — «сейчас найду…» и конец хода. Фикс: запрет
   заканчивать ответ обещанием.

**Ошибки, найденные живым использованием** (промптом не чинятся — закрыты
инвариантами в коде, каждый — оффлайн-тестом):

| Сбой модели | Гарантия в коде |
|---|---|
| «Обновила корзину словами» — фальшивая сумма без вызова | regex-детектор утверждения → принудительный повтор; обещание ссылки — пересбор без LLM |
| `replace=true` и повторный `create_cart` за ход теряли позиции | флаг убран, состав передаётся между вызовами; удаление только через `quantity=0` |
| Удаляла не тот товар (просили печенье — убрала суп) | сверка удаляемого с репликой пользователя + `confirm_removals` |
| Передавала состав без удаляемого — винегрет оставался | автосъём по названию: «убери винегрет» убирает его, даже если модель не передала id |

**Ограничения eval:** проверки детерминированные (суммы, составы, источники
id, URL), субъективное качество текста не оценивается; кейсы гоняются по
живым данным ВкусВилла — бюджетные суммы могут флуктуировать.
