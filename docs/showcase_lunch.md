# Эталонный пример: от запроса до корзины

Автогенерируется раннером eval из фактического лога прогона — всё ниже
реальные ответы модели и данные ВкусВилла на момент прогона.

**Запрос покупателя (3 хода):**

1. «Собери полноценный обед для одного взрослого человека. Сразу собери корзину.»
2. «Замени салат на винегрет»
3. «Сколько углеводов суммарно содержится в продуктах из корзины?»

**Что считается подходящим результатом** (проверяется детерминированно):

- после хода 1 собрана корзина (≥ 3 позиций: основное + гарнир/овощи + напиток),
  все id — из результатов инструментов, ссылка ведёт на vkusvill.ru;
- после хода 2 винегрет в корзине, салата нет (если был), остальные позиции
  хода 1 сохранились — корзина только накапливается;
- в ходе 3 по каждой позиции корзины запрошен свежий состав/КБЖУ
  (get_product_details), суммарные углеводы в ответе сходятся с пересчётом
  по весу упаковок из ответов ВкусВилла (допуск ±30% на округления).

**Что получает модель на вход** (каждый ход; сборка — `app/agent.py`,
`_with_system_prompt`; промпт — `app/prompts.py`):

- системное сообщение: статический SYSTEM_PROMPT (роль, правила работы с
  инструментами и общения) + динамический контекст — «Показанные
  пользователю товары (последняя подборка): …» и «Текущая корзина: id=… ×…»,
  если они есть;
- очищенную историю сообщений: служебные блоки состояния
  `[Показаны товары: …]` / `[В корзине: …]` вырезаются из реплик ассистента
  и переносятся в системный промпт — состояние приходит один раз, в контексте;
- схемы 7 инструментов (`app/tools/schemas.py`).

В ходе 1 корзины и подборок ещё нет — модель получает голый SYSTEM_PROMPT +
реплику покупателя и сама раскладывает «полноценный обед» на категории
(отсюда её `search_products("первое блюдо")` и далее). В ходах 2–3 в системном
промпте уже есть контекст корзины, поэтому «салат» и «винегрет» разрешаются
в реальные id без выдумывания. Промпт задаёт поведение, но критичные гарантии
(переспрос вместо сбора корзины, «обновление словами», tool call текстом)
закрыты инвариантами кода агентного цикла — см. README.

**Прогон:** ✅ Все проверки пройдены

## lunch_showcase — ✅ PASS

_эталонный пример «от запроса до корзины»: обед → замена салата на винегрет → суммарные углеводы_

Проверки кейса:
- инструмент search_products вызывался
- корзина собрана (событие cart есть) — без неё проверки корзины не имеют смысла
- в финальной корзине не менее 3 позиций
- все id товаров корзины — из результатов search_products / find_product_analogs (анти-галлюцинации)
- ссылка каждой корзины ведёт на vkusvill.ru
- каждая названная в ответе сумма сходится с фактической суммой корзины из события cart (±5%); сумма без вызова create_cart — нарушение
- финальный ответ не пуст
- ход 2: «винегрет» появился в корзине, «салат» исчез (если был), остальные позиции хода 1 сохранились
- по каждой позиции последней корзины запрошен свежий get_product_details; суммарные углеводы в ответе сходятся с пересчётом (углеводы/100 г × вес упаковки × количество, допуск ±30%)
