# Архитектура сервиса «Вкусный ассистент»

Как устроен сервис после всех доработок (октябрь 2026). Дополняет README; для защиты — это техническое описание, для себя — карта кода.

## Общая картина

```
Браузер (vanilla JS)                          VPS 176.12.68.185
┌──────────────────────┐    POST /api/chat    ┌─────────────────────────────┐
│ история в localStorage│ ──────────────────► │ nginx :80                   │
│ SSE-парсер вручную   │ ◄────────────────── │  └ uvicorn 127.0.0.1:8000   │
│ markdown-рендер      │   поток SSE-событий │     └ FastAPI → Agent        │
└──────────────────────┘                     │        ├ YandexGPT API      │
                                             │        └ MCPClientManager   │
                                             │           └ mcp.vkusvill.ru │
                                             └─────────────────────────────┘
```

Сервер **полностью stateless**: никакой базы, никакой сессии. Всё состояние диалога
живёт в браузере (localStorage) и приходит в каждом запросе целиком. Это упрощает
деплой (systemd + nginx, один процесс) и делает сервис устойчивым к перезапускам.

## 1. Фронтенд — `app/web/static/app.js`

- **История**: массив `{role, content}` в localStorage (последние 40 сообщений —
  защита от раздувания контекста, то же ограничение на бэкенде).
- **Стриминг**: `fetch` + `ReadableStream` (EventSource не умеет POST).
  SSE-сообщения парсятся вручную по `\n\n`.
- **События**, которые приходят с сервера:
  - `token` — кусочек текста ассистента (дописывается в «пузырь» сообщения);
  - `tool` — чип «Ищу товары…» / «Собираю корзину…»;
  - `products` — карточки товаров (картинка, цена, старая цена, рейтинг, ссылка);
  - `cart` — собранная корзина: состав, сумма, зелёная кнопка «Открыть корзину ВкусВилл»;
  - `error` / `done`.
- **Markdown** — свой мини-рендер без зависимостей (заголовки, списки, ссылки,
  жирный/курсив, код), финальный ответ перерисовывается целиком после `done`.
- **Ключевой трюк — служебные блоки как носитель состояния.** После каждого
  ответа фронтенд дописывает в конец сообщения ассистента невидимые пользователю
  блоки:

  ```
  [Показаны товары: id=58289 Печенье сдобное «Шоколадное», 300 г; …]
  [В корзине: id=58289 Печенье сдобное ×1; id=60658 Суп «Рассольник» ×1]
  ```

  По ним на следующем запросе сервер понимает, что значат «этот товар» и «текущая
  корзина». При рендере эти блоки вырезаются (плюс эвристика против подделок —
  любая отдельная строка в квадратных скобках с маркерами `id=`/«товар»/«корзин»
  скрывается).

## 2. Бэкенд — `app/main.py`

Один эндпоинт `POST /api/chat`: принимает историю, фильтрует только
`user`/`assistant`, обрезает до 40 сообщений и запускает агента, заворачивая его
события в SSE через `asyncio.Queue`. Заголовки `Cache-Control: no-cache` +
`X-Accel-Buffering: no` — чтобы nginx не буферизовал стриминг.
`logging.basicConfig(level=logging.INFO)` — вызовы инструментов видны в
`journalctl -u vkusvill`.

## 3. Агентный цикл — `app/agent.py`

`Agent.run(messages, emit)` не знает про HTTP — поэтому веб, CLI и eval
используют один и тот же цикл.

**Подготовка контекста** (каждый запрос):

1. Из истории извлекаются корзина (`current_cart_from_history`) и названия её
   товаров (`cart_names_from_history`), последняя подборка товаров
   (`last_shown_products_from_history`).
2. Служебные блоки **вырезаются из всех сообщений** — модель их никогда не видит
   в истории и не может скопировать в свой ответ.
3. Вместо них в системный промпт дописывается раздел контекста:

   ```
   Показанные пользователю товары (последняя подборка): […]
   Текущая корзина: id=58289 ×1; id=60658 ×1
   ```

**Цикл** (до `max_tool_iterations`):

- запрос к YandexGPT (OpenAI-совместимый API, стриминг, tool calling);
- текстовые дельты → `emit("token")` — сразу пользователю;
- tool calls приходят **фрагментами**, копятся по `index`; невалидный JSON в
  аргументах возвращается модели как `TOOL_ERROR` — она самокорректируется;
- вызов инструмента → `emit("tool")` → обёртка → MCP → результат в историю как
  `role=tool`;
- когда модель отвечает чистым текстом — цикл завершается.

**Три гарантии на финальном ответе** (срабатывают, если модель «обещала,
но не сделала»):

1. **Утверждение об изменении корзины без вызова `create_cart`** («Суп добавлен
   в корзину», «я убрал печенье» — обе ориентации слов, только утвердительные
   формы глаголов) → пользователю показывается «_Оформляю корзину…_», а модели
   в историю добавляется системная поправка с требованием вызвать инструмент.
   Цикл продолжается.
2. **Обещание ссылки на корзину без вызова** («ссылка появится под сообщением»)
   при непустой корзине → агент вызывает `create_cart` **сам, без LLM**, с
   точным составом и количествами из контекста. Детерминированно — модель не
   может переврать количество.
3. Если и это не удалось — та же системная поправка, что и в п. 1.

## 4. Инструменты — `app/tools/`

7 обёрток над MCP-инструментами (не passthrough): `search_products`,
`get_product_details`, `find_product_analogs`, `search_discounted_products`,
`find_recipes`, `find_shops`, `create_cart`. Обёртки режут лишние поля (экономия
токенов), чистят HTML-сущности (`&nbsp;`), заполняют 8 обязательных параметров
рецептов, эмитят богатые события (`products`/`cart`) в UI, ошибки возвращают
как строки `TOOL_ERROR: …` — модель извиняется и предлагает альтернативу вместо
500-й ошибки.

**`create_cart` — самый нагруженный инвариантами инструмент:**

- Агент подставляет в него скрытые аргументы: `_current_cart` (текущий состав),
  `_cart_names` (id → названия), `_last_user_message` (последняя реплика
  пользователя).
- Корзина **только накапливается**: переданные товары объединяются с текущими,
  `replace` больше не существует — модель физически не может молча потерять
  позицию.
- Дубликаты в одном вызове суммируются; новое количество затирает старое;
  **удаление — явно, через `quantity=0`**; не упомянутые позиции всегда остаются.
- **Защита от подмены при удалении**: если модель удаляет товар, которого
  пользователь не упоминал, а упомянул товар, который она оставляет (просили
  убрать печенье — она убирает суп), вызов отклоняется с подсказкой: цитата
  запроса, список корзины с id, и обходной путь `confirm_removals=true`, если
  модель уверена. Живой прогон показал: модель дважды упёрлась, дважды получила
  отказ, на третий раз удалила правильный товар. Формулировки без названий
  («номер 1», «оставь только суп») не блокируются — нет сигнала подмены.
- После успеха обёртка возвращает финальный состав (`_final_cart`) агенту —
  **последовательные `create_cart` внутри одного хода объединяются**, а не
  затирают друг друга.
- Валидация: 1–20 позиций, количество 0–40; цены подтягиваются параллельными
  запросами `product_details`, считается сумма.

## 5. MCP-клиент — `app/mcp_client.py`

Один менеджер на приложение (lifespan FastAPI), `streamablehttp_client` к
`https://mcp.vkusvill.ru/mcp`. Сервер stateless, rate limit 60 запросов/3 сек →
`Semaphore(3)` и ретраи с паузами; при сбое сессия лениво переоткрывается.
Конверт ответов `{"ok", "data"/"error"}` разбирается центрально,
`ok: false` → исключение → `TOOL_ERROR`.

## 6. Состояние корзины — сквозная схема

```
событие cart (сервер) → localStorage (кнопка живёт после перезагрузки)
                      → блок [В корзине: …] в истории (носитель состояния)
следующий запрос:  блок → вырезается из истории → раздел контекста в системном промпте
                  + id/названия/реплика пользователя → в create_cart для инвариантов
```

Единственный источник правды о корзине — этот блок; модель видит корзину только
через системный промпт и изменить её может только реальным вызовом `create_cart`,
который проходит через все проверки обёртки.

## 7. Деплой

VPS (FirstVDS, Ubuntu 24.04): systemd-сервис `vkusvill` (uvicorn на
127.0.0.1:8000) за nginx на 80-м порту с `proxy_buffering off`. Обновление:

```bash
git push
ssh root@176.12.68.185 "cd /opt/vkusvill && git pull -q && systemctl restart vkusvill"
```

Ключ LLM — только в `.env` на сервере (в репозитории отсутствует). SSH — только
по ключу, парольный вход отключён.

## 8. Качество

- **37 оффлайн-тестов** (pytest, FakeLLM со скриптованными чанками + FakeMCP с
  canned-ответами): цикл, накопление tool calls, невалидный JSON, лимит шагов,
  перенос блоков в промпт, все инварианты корзины, regex-паттерны, SSE-эндпоинт.
- **Eval-раннер** (7 кейсов: бюджет/безлактозный перекус, рецепты, скидки,
  пустой результат, аналоги, уточнение, недоступный источник) — тот же
  `Agent.run`, без HTTP.
- Живая проверка на проде сценариями через curl — накопление корзины, замена
  позиций, удаление, ссылка.

## Философия проекта

**Инварианты — в коде, а не в промпте.** YandexGPT регулярно «обновляет корзину
словами», выдумывает id, путает товары и копирует служебные форматы — каждый
такой случай закрыт проверкой в коде, а промпт лишь направляет модель в
правильную сторону.

| Сбой модели | Защита в коде |
|---|---|
| Пишет «добавлено в корзину» без вызова инструмента | regex-детектор + принудительный повторный заход |
| Обещает ссылку, не вызывая `create_cart` | прямой детерминированный пересбор без LLM |
| Выдумывает id товаров | id только из раздела контекста; ошибка сборки возвращает модель к поиску |
| Копирует служебные блоки в ответ | блоки вырезаются из истории; фильтр при рендере |
| Пересобирает корзину с потерей позиций (`replace`) | флаг удалён; обёртка только накапливает |
| Затирает первый вызов вторым `create_cart` в одном ходе | `_final_cart` — накопление внутри хода |
| Удаляет не тот товар | сверка удаляемого с репликой пользователя |
